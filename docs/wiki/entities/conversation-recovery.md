## 职责

保存微信对话的 pi 会话，重启后在下一次对话时恢复上下文，并报告任务进度、失败与停止状态。

## 关键文件与接口

- src/pi/conversation-store.ts：使用 SDK SessionManager 保存和打开 JSONL 会话，不自行解析会话格式。状态目录下 sessions 保存历史，current.json 原子切换当前会话。
- src/pi/sessions.ts：复用持久会话；对话与 /new 使用同一串行队列；每条任务开始后才绑定其图片回复上下文。
- src/message/task-notifier.ts：开始确认、每 30 秒进度、最终通知串行发送；工具参数和原始错误不进入通知。
- src/bridge.ts：账号和微信对话构成会话标识，报告耗时和处理阶段；普通回复作为完成结果，无文本时提示完成；失败和停止分别提示。
- src/message/task-queue.ts：同一对话从附件处理到回复发送全流程串行，其他对话独立。/new 和设置下一条消息指令也按接收顺序执行。

## 上下游依赖

复用现有 pi SDK 与 Node 标准库。会话目录用工作目录和会话标识的 SHA-256 值隔离，避免目录名包含微信标识及路径分隔符。POSIX 目录 700、文件 600；Windows 依赖用户目录权限。

## 重要变更记录

2026-09-30：类型检查、构建与全部测试通过（115 通过，1 项 POSIX 权限测试在 Windows 跳过）。新增跨 Node 进程读取 SDK 会话、/new 后立即恢复、目录隔离、索引损坏与显式重置、取消任务后的队列恢复、通知节流及生命周期测试。/new 保留旧记录且保存新会话头，保证立即重启后不恢复旧上下文。恢复已保存的对话，不自动重做重启前未完成的任务。服务退出信号关闭通知并请求中断模型任务。

## 使用边界

历史会话使用 /sessions、/resume、/rename 和 /export 管理。SDK 的 UUID v7 在相近创建时间可能共享前八位，列表必须展示完整编号；恢复接受唯一前缀，但前缀不唯一时拒绝。真实文件验证发现此边界，已修正列表展示。

/tasks 列出当前对话尚未结束的任务编号、等待/处理/停止状态与耗时，最多展示前 20 条。/cancel 接受至少 8 位任务编号前缀，仅取消该对话匹配的一条任务；前缀不唯一时报错，其他任务继续。任务摘要最多 60 字符，只向当前对话展示；内存队列列表不持久化，但独立 TaskJournal 保存任务记录，重启后标记未完成记录为中断。/history 与 /result 查询持久记录，/retry 需要再次确认，见 [微信功能服务与权限](feature-services.md)。真实文件任务验证了列表、命令响应、编号校验、对话隔离、单独取消当前或等待任务，以及完成后列表清理；128 项测试通过、1 项 Windows 不适用权限测试跳过，类型检查和构建通过。

/stop 绕过队列，取消当前对话正在处理和已经等待的任务，取消范围包含附件下载、重试等待、anydoc 转换与模型请求。停止后新收到的消息仍可执行；/ping、/help、/status、/usage 直接响应。真实 PDF 与 Word 转换验证了顺序及其他对话独立执行；取消当前和等待任务后，新任务仍能读取文件，真实文件读取失败不阻塞后续任务。

不自动删除历史；会话中可能包含用户消息、图片和工具结果，需要维护者管理状态目录。存储损坏或当前文件缺失时明确失败，可用 /new 新建会话，不静默丢失历史。
